# NetVision

NetVision — настольное приложение для наглядной диагностики собственного интернет-соединения. Оно показывает локальный интерфейс, DNS, ping/jitter/loss, TCP/TLS и маршрут до указанного пользователем узла.

## Возможности версии 0.7

- сетевые интерфейсы, IPv4/IPv6, MAC, состояние и скорость;
- основной IPv4-шлюз и системные DNS-серверы Windows;
- внешний IP и обнаруженные системные прокси;
- параллельные измерения DNS, ICMP ping, потерь, jitter, TCP и TLS;
- версия TLS, шифр, ALPN и сведения о сертификате;
- маршрут `tracert` с задержкой и тайм-аутами;
- ASN, организация, провайдер и GeoIP публичных адресов на пути;
- сравнение доступных default routes с распознаванием VPN-интерфейсов;
- интерактивная карта: щелчок по узлу открывает подробности;
- фоновая диагностика без зависания интерфейса;
- журнал предупреждений и ошибок.
- экспорт полного отчёта в JSON.
- быстрые системные действия: очистка DNS-кэша и переход к настройкам адаптеров, прокси и брандмауэра Windows.
- подсказки по DNS, Ping, потерям, Jitter, TCP и TLS через значки `?`;
- два режима интерфейса: «Эксперт» с картой и подробными таблицами и «Простой режим» с понятным итогом.
- инспектор процессов: поиск запущенных приложений с активными TCP/UDP-соединениями и выбор IP/порта;
- автоматическая подстановка endpoint процесса и анализ возможной причины дисконнекта.
- вкладка «Качество» с автономным HTTP-тестом на чистом Python;
- загрузка 10 МБ через Cloudflare CDN или OVH с расчётом download в Мбит/с;
- TCP-пинг к `1.1.1.1:53` или `8.8.8.8:53`;
- внешний IPv4/IPv6, провайдер и регион через JSON API `ip-api.com` и `ipwho.is`;
- итоговая сводка, сопоставляющая результат теста, внешний IP и скорость локального адаптера.

Приложение проверяет только узел, явно указанный пользователем. Оно не выполняет массовое сканирование портов и не изменяет настройки сети, VPN или прокси.
GeoIP-запросы отправляются в публичные JSON API только во время запуска проверки качества. При экспорте JSON имя пользователя и пароль в адресах прокси удаляются.

## Требования

- Windows 10 или Windows 11;
- Python 3.11 или новее;
- доступ к PowerShell, `tracert` и интернету для полной диагностики;

## Установка и запуск

Откройте PowerShell в папке проекта и выполните:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m netvision
```

Введите домен, IP-адрес или URL, укажите TCP-порт и нажмите «Запустить диагностику». Для HTTPS обычно используется порт `443`.

В блоке «Быстрые действия» доступны системные операции Windows. «Сброс DNS» выполняет `ipconfig /flushdns` без консольного окна и пишет результат в журнал. Остальные кнопки открывают соответствующие системные панели; они не изменяют настройки автоматически.

Переключатель «Эксперт / Простой режим» находится в шапке окна. Простой режим показывает цветной итог: зелёный означает стабильное соединение, жёлтый — доступный сайт с предупреждениями, красный — ошибку DNS или недоступный TCP-порт.

В блоке «Процесс / игра» NetVision показывает приложения с активными соединениями, PID и endpoints. Выбор endpoint подставляет IP и порт в поля диагностики; сама диагностика запускается отдельно кнопкой. Для UDP-цели TCP-результат не считается доказательством блокировки игрового порта.

На вкладке «Качество» кнопка «Проверить качество» запускает HTTP-загрузку, TCP-пинг и JSON-запросы Geo API в отдельном потоке. Сторонние бинарники и установка Speedtest не требуются.

Скорость адаптера в сводке — это согласованная скорость локального Wi-Fi/Ethernet-соединения, не скорость интернет-тарифа. HTTP-тест измеряет только download; upload и loaded ping помечаются как недоступные, чтобы не выдавать оценку за реальное измерение.

NetVision больше не использует HTML-скрейпинг Яндекс Интернетометра. Данные получают только из JSON API `ip-api.com` и `ipwho.is` с браузерным User-Agent. Обнаружение VPN/прокси является эвристическим: учитываются локальные интерфейсы, default route, системные proxy и признаки, возвращённые API.

В поле «Локальный IP» показываются только основной активный IPv4 и IPv4 VPN-интерфейса. Служебные `169.254.*`, IPv6 и остальные адреса доступны в подсказке при наведении.

## Проверка проекта

```powershell
python -m unittest discover -s tests -v
```

Ping выполняется пять раз; jitter считается как среднее абсолютное изменение между последовательными полученными RTT. Высокая потеря ICMP может означать фильтрацию ping узлом, даже если TCP-соединение работает.

Сравнение маршрутов показывает текущие записи default route и их метрики. Оно не отключает VPN и не проверяет альтернативный путь, пока сетевой маршрут системы не изменён отдельно.

## Ограничения MVP

- сбор шлюза и DNS сейчас ориентирован на Windows;
- `tracert` может занимать несколько секунд и отдельные узлы могут не отвечать на ICMP;
- внешний IP определяется через два публичных JSON API; при их недоступности остальные проверки продолжаются;
- HTTP CDN, GeoIP и TCP-пинг требуют доступа к внешней сети и могут быть недоступны через отдельные VPN или прокси;
- сравнение отражает маршруты, присутствующие в системной таблице Windows в момент проверки.
